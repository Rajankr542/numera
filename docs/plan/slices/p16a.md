# P16-A slice plan (D-191–D-199)

Branch: `p16a` | File: `packages/numera/src/p16a.ts`

## Scope
Pure-TypeScript quick wins to close the coverage gap toward 98%:

1. **Math/bool/sentinel constants** — `pi`, `e`, `inf`, `nan`, `euler_gamma`,
   `True_`, `False_`, `PINF`, `NINF`, `PZERO`, `NZERO` (plus `newaxis` already exists).
2. **Dtype alias constants** — `double`, `single`, `half`, `int_`, `intc`, `intp`,
   `byte`, `short`, `ubyte`, `ushort`, `uint`, `uintc`, `uintp`, `cdouble`, `csingle`,
   `longdouble`, `clongdouble`, `long`, `ulong`.
3. **`np.vectorize(fn, opts?)`** — wraps a JS callback, returns a callable that
   applies it element-wise over NDArray inputs (broadcast together, output dtype
   from `otypes` or inferred at first call). Pure TS loop.
4. **`np.shares_memory(a, b, opts?)`** — delegates to existing
   `mayShareMemory` (native buffer identity + byte-range overlap). `maxWork` is
   accepted but ignored (consistent with NumPy 2 semantics).
5. **NDArray methods `cumsum` / `cumprod`** — declaration merging; implemented
   via `add.accumulate` / `multiply.accumulate` from `ufunc.ts`.

## Decision D-191 — P16-A constants, vectorize, shares_memory (P16-A) — Accepted — 2026-10-02

- Math constants are plain JS primitives re-exported under their NumPy names.
- `PINF = Infinity`, `NINF = -Infinity`, `PZERO = 0`, `NZERO = -0` are aliases.
- Dtype aliases are `DType` singleton instances from `dtype.ts`, same objects
  as `np.float64` etc., just re-exported with the NumPy alias names.
  `int_` → int64 (64-bit default on NumPy's 64-bit platforms), `intc` → int32,
  `intp` → int64, `long` → int64, `ulong` → uint64, `uint` → uint64,
  `uintc` → uint32, `uintp` → uint64, `byte` → int8, `short` → int16,
  `ubyte` → uint8, `ushort` → uint16, `double` → float64, `single` → float32,
  `half` → float16, `cdouble` → complex128, `csingle` → complex64,
  `longdouble` → float64 (no 80-bit float in JS), `clongdouble` → complex128.
- `True_` is the JS boolean `true`; `False_` is `false`.  They are not
  np.bool_ instances because numera has no scalar class hierarchy.
- `vectorize(fn, {otypes?, signature?})`: `signature` is accepted but currently
  only `None` (scalar-in scalar-out) is supported; a non-null signature throws
  `ValueError("signature not supported")`. Output dtype: first element of
  `otypes` if given (must be a single dtype); otherwise inferred from the return
  value of `fn` on the first call. The returned function also has a `.pyfunc`
  property pointing back to the original `fn`.
- `shares_memory(a, b, {maxWork?})`: delegates to `mayShareMemory` (native
  `sharesMemory`); `maxWork` is accepted and ignored.
- `cumsum(axis?, {dtype?})` / `cumprod(axis?, {dtype?})`: NDArray methods added
  via declaration merging; internally use `add.accumulate` / `multiply.accumulate`.

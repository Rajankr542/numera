# numera Architecture

See `docs/plan/PLAN.md` for the full specification; this file documents what
is actually implemented and how the pieces fit.

## Layers
```text
packages/numera/src (TypeScript public API, validation, ergonomics)
        │  loads build/Release/nativpy.node (addon.ts)
        ▼
native/bindings  (Node-API via node-addon-api; error translation)
        ▼
native/core      (nativpy_core static lib, no Node dependency)
   memory.hpp   MemoryBuffer: aligned RAII allocation
   dtype.hpp    DType enum + DTypeInfo (size, alignment, kind), promotion
   shape.hpp    shape validation, size, axis normalization
   strides.hpp  C-contiguous strides, contiguity checks, bounds checks
   ndarray.hpp  NDArray: buffer + dtype + shape + strides(bytes) + offset(bytes)
   error.hpp    typed error hierarchy (ErrorKind)
   ufunc.hpp    enum ufunc API (BinaryOp/UnaryOp), UfuncParams, result layout
   ufunc_registry.hpp  one immutable `Ufunc` record per ufunc (D-051):
                name, nin, identity, type resolvers, per-dtype loop tables;
                `find_ufunc(name)` and the generic out/where/dtype/order drivers
```
Future: `native/kernels`, `native/linalg`, `native/random`, `native/fft`,
`native/simd`, `native/threading` (created when their milestone starts).

## NDArray (native/core/ndarray.hpp)
- `buffer_`: `shared_ptr<MemoryBuffer>`; shared by all views.
- `strides_`/`offset_`: **bytes** (D-003).
- `data()` = `buffer->data() + offset`.
- `view(shape, strides, offset)` creates a new NDArray on the same buffer after
  bounds validation. `reshape` returns a view when the array is C-contiguous,
  otherwise copies (full stride-aware reshape arrives in M3).
- `copy()` produces a C-contiguous copy via a generic strided element loop.
- Element access: `getAsDouble/setFromDouble` (and int64/uint64 variants)
  through dtype dispatch (`dispatch_dtype`).

## Binding (native/bindings)
- `NDArrayWrap` (`Napi::ObjectWrap`) owns an `NDArray` by value; JS GC of the
  wrapper drops one buffer reference. The addon is built with `NAPI_EXPERIMENTAL`
  (CMake `NATIVPY_NAPI_EXPERIMENTAL`, D-023), so this basic finalizer runs
  synchronously inside GC. It must stay basic: no JS calls and no allocation of
  JS values. `NODE_ADDON_API_REQUIRE_BASIC_FINALIZERS` enforces this at compile time.
- Functions exported: `empty/zeros/fromData`, properties, `toList`,
  `toTypedArray`, `view`, `reshape`, `copy`, `astype`, `sharesMemory`.
- All entry points wrap with `translate_errors` → typed JS errors.

## TypeScript (packages/numera/src)
- `NDArray` class wraps a native handle; `np` default export.
- `dtype.ts` exposes dtype objects (`np.float32`, …) and name normalization.
- `errors.ts` defines `NativpyError` subclasses matching `ErrorKind`.

## Testing
- `tests/native/` C++ unit tests (CTest), also run with ASan+UBSan.
- `packages/numera/test/` vitest unit tests through the real addon.
- `tests/differential/` + `python/`: JSON cases generated by NumPy, replayed by
  numera, compared on dtype/shape/strides/values.
